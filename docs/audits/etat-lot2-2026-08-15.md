## Problèmes rencontrés → arbitrages à poser à Maël

- **A1 — L'« entité affectée » de D7 est hors typologie v1** (E015, E077, G005). D7 : crise agrégée → principal = entité affectée (« protocole Bitcoin »). Or `acteur_principal` ne connaît que les 7 types d'acteurs : « protocole Bitcoin » est inexprimable. L'épreuve l'a noté `[hors typologie v1]` sans toucher au maître. Options : (a) autoriser un nom d'entité hors typologie dans `acteur_principal` ; (b) ajouter une valeur dédiée type `systeme_protocole` ; (c) colonne `entite_affectee` séparée. Contre-exemple qui marche : E055 (entité affectée = MtGox → `entrepreneurs_exchanges`, exprimable).
- **A2 — Incident subi sans initiateur énoncé** (E029 flash crash) : acte ponctuel, mais D7 (« principal = initiateur ») est muette quand personne n'initie. Posé `a_arbitrer` dans l'épreuve. Proposition : étendre « entité affectée » aux incidents subis, même ponctuels.
- **A3 — Trou Q7 : émission / rareté / intégrité du monnayage.** Trois lignes butent sur la même absence : E015 (« enregistrement à émission surnuméraire »), E077 (« touche aux sacro-saintes règles de monnayage »), G069 (« calendrier d'émission prévu par le protocole »). Aucune des huit dimensions ne code l'objet propre de ces énoncés. Options : dimension nouvelle `integrite_monnayage` (ou `rarete_emission`), ou règle documentée « monnayage → conf_methodique ». **C'est l'ambiguïté structurante au sens D11.**
- **A4 — Convention multi-effets** : le calibrage n'a que des effets simples `dimension(+/-)` ; l'épreuve en a eu besoin de 2-3 par ligne (E029, E044, E052). Convention utilisée dans les fichiers d'épreuve : liste séparée par espaces (`conf_methodique(-) valorisation(-)`). À ratifier avant tout report au maître.
- **A5 — Frontière `conf_ethique` / `conf_methodique`** sur le fork The DAO (F069) : les valeurs priment le code, puis sécession — l'épreuve a codé `conf_ethique(±)` ; un guide de frontières est à écrire au moment du gel.
